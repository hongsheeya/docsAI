FallAI — 낙상 위험 영상 분석 시스템

FallAI는 RF-Dual 낙상 확률과 XG-Posture 5-class 자세를 함께 사용해 낙상 위험 여부를 설명 가능한 형태로 보여주는 운영형 프로토타입입니다.

영상 업로드 분석

MP4, MOV, AVI 등 영상 파일을 업로드하면 AI가 낙상 위험을 판단합니다.

실시간 웹캠 분석

4초 단위 연속 청크를 누락 없이 순차 분석하고 큐 적체와 재시도를 표시합니다.

위험 알림 전송

낙상 감지 시 보호자 알림/응급 안내 워크플로를 확인할 수 있습니다.

분석 모드 선택

분석 작업 영역 상단에서 두 가지 입력 모드를 전환할 수 있습니다.

업로드 모드

저장된 영상 파일을 직접 업로드하여 전체 결과와 분할 로그를 함께 확인합니다. 드래그 앤 드롭 또는 파일 선택 버튼을 사용합니다.

실시간 모드

웹캠을 연결하여 4초 연속 청크를 녹화·분석합니다. 큐는 청크를 버리지 않고 순차 전송합니다.

분석 설정

분석 모델 선택

RF-Dual (현재 운영): RF 낙상 확률 + XG-Posture 5-class 자세를 결합해 낙상 여부와 이유를 함께 설명합니다.

XG-Posture의 역할: sit / lie / fall 경계 사례를 분리하고 fast-sit, controlled-lie 같은 오탐을 줄이는 설명 레이어입니다.

업로드 분석 상세

업로드 분석 절차

  1. 업로드 모드 버튼이 선택된 상태인지 확인합니다.
  2. 분석할 영상 파일을 드래그 앤 드롭하거나, 파일 선택 버튼을 클릭하여 파일을 고릅니다.
  3. 지원 형식: MP4, MOV, AVI, MKV, WEBM
  4. 영상이 미리보기 영역에 표시되고 파일 정보(크기, 길이, 해상도)가 나타납니다.
  5. 원하는 분석 프로파일과 모델을 선택합니다.
  6. 즉시 분석 버튼을 클릭합니다.
  7. 업로드 진행률 바가 표시되고, 서버 분석이 완료되면 전체 결과와 청크별 분할 로그가 아래에 나타납니다.

주의 사항

  • 영상 파일 크기가 클수록 업로드와 분석에 시간이 더 걸립니다.
  • 분석 중에는 다른 영상을 업로드할 수 없습니다.
  • 업로드는 단일 패스로 분석하고, 실시간 모드에서만 4초 연속 청크 로그를 생성합니다.
  • 초기화 버튼으로 현재 선택된 파일과 결과를 모두 지울 수 있습니다.

실시간 웹캠 분석

웹캠을 이용하면 카메라 앞의 상황을 실시간으로 분석할 수 있습니다. 현재는 4초 단위 청크를 끊김 없이 생성하고, 서버 RTT가 튀어도 브라우저 큐에서 청크를 버리지 않습니다.

실시간 분석 절차

  1. 실시간 모드 버튼을 클릭하여 모드를 전환합니다.
  2. 웹캠 연결 버튼을 클릭합니다. 브라우저에서 카메라 권한을 물으면 허용을 선택합니다.
  3. 웹캠 화면이 미리보기 영역에 표시됩니다.
  4. 실시간 분석 시작 버튼을 클릭합니다.
  5. 4초 단위 영상 청크가 자동 전송되어 RF-Dual 낙상 판단과 XG-Posture 행동분류가 병렬로 수행됩니다.
  6. 서버 처리 시간이 길어지면 큐에 쌓아두고 실패 청크는 재시도합니다.
  7. 분석 결과와 한 줄 설명 로그가 실시간으로 갱신되며, 낙상이 감지되면 알림 워크플로가 자동 실행됩니다.
  8. 실시간 분석 종료 버튼으로 분석을 중단할 수 있습니다.

주의 사항

  • 웹캠 기능은 HTTPS 또는 localhost 환경에서만 동작합니다.
  • 브라우저가 MediaRecorder API를 지원해야 합니다 (Chrome, Edge 권장).
  • 이전 분석이 끝나기 전에 새 청크가 도착하면 대기열에 추가됩니다.
  • 중복 낙상 알림은 4초 내에는 자동으로 억제됩니다.

분석 결과 보기

분석이 완료되면 결과 영역에 다양한 정보가 표시됩니다. 각 항목의 의미를 안내합니다.

낙상 감지 여부

AI가 영상에서 낙상 후보를 감지했는지 여부입니다. "낙상 후보 감지"(빨간색) 또는 "즉시 낙상 아님"(녹색)으로 표시됩니다.

행동 분류

영상에서 감지된 행동의 유형입니다. (예: "일상 행동", "낙상 의심 행동" 등)

위험 점수 (Risk Score)

0%~100% 사이의 수치로, 값이 높을수록 낙상 위험이 높다고 판단합니다. 기준값(Threshold) 이상이면 "낙상"으로 판정합니다.

분석 모드

실제로 사용된 분석 프로파일과 모델 정보입니다.

빠른 요약

분석 결과를 한 줄로 요약한 텍스트입니다.

판단 근거

AI가 판단에 사용한 각 지표(Y축 변위, 하강 가속도, 자세 높이, 종횡비 변동 등)의 수치와 위험 수준을 카드로 표시합니다.

이벤트 후보 구간

영상 내에서 낙상 의심 이벤트가 감지된 시간 구간과 신뢰도를 표시합니다.

분석 진단 메모

분석 과정에서 발생한 참고 사항이나 경고를 표시합니다. (예: "사람이 감지되지 않음", "프레임 수 부족" 등)

한 줄 로그 설명

각 로그에는 구간, 위험도, 자세, 판정 상태를 한 줄로 요약한 설명이 추가됩니다.

피드백 및 재학습 (HITL)

분석 결과가 정확한지 사용자가 직접 검증하고 피드백할 수 있습니다. 이 피드백은 모델 재학습에 활용되어 시간이 지날수록 분석 정확도가 향상됩니다.

피드백 절차

  1. 분석 결과 하단의 "결과 검증 피드백" 영역으로 이동합니다.
  2. 결과가 맞으면 맞아요, 틀리면 틀려요 버튼을 클릭합니다.
  3. "틀려요"를 선택한 경우, 실제 정답이 낙상(Y)인지 비낙상(N)인지 선택합니다.
  4. 필요하면 메모를 작성합니다.
  5. 피드백 저장 버튼으로 저장만 하거나, 피드백 저장 + HITL 재학습 버튼으로 저장과 함께 모델 재학습을 요청할 수 있습니다.

HITL(Human-In-The-Loop) 재학습이란?

사용자의 피드백 데이터를 모델 학습에 반영하여 점진적으로 정확도를 개선하는 방식입니다. 피드백이 누적될수록 AI 모델이 해당 환경에 더 적합하게 학습됩니다.

위험 알림

낙상이 감지되거나 위험 점수가 기준 이상일 경우, 보호자에게 알림을 전송하고 119 연락 안내 팝업을 표시합니다.

알림 흐름

  1. 분석 결과에서 낙상 감지 또는 중/고 위험 판정이 나오면 "위험 알림 워크플로" 영역이 나타납니다.
  2. 보호자/응급 알림 전송 버튼을 클릭하면 설정된 보호자에게 알림이 전송됩니다.
  3. 고위험 판정 시 119 연락 안내 팝업이 자동으로 표시됩니다.

실시간 모드에서의 자동 알림

중복 낙상 알림은 5초 이내에는 자동으로 억제하여 불필요한 알림을 방지합니다.

AI 파이프라인

파이프라인 페이지( /pipeline )에서는 AI 분석 시스템의 내부 구조와 학습 데이터 현황을 확인할 수 있습니다.

주요 확인 항목

분석 엔진 요약

현재 서비스되는 분석 엔진(RF-Dual 중심, posture 설명 포함)의 이름, 상태, 설명을 확인합니다.

학습 데이터 통계

낙상/비낙상 학습 샘플 수, 행동 분류 데이터 현황을 확인합니다.

분석 파이프라인 흐름

RF-Dual, XG-Posture, 4초 실시간 청크 정책까지 포함한 단계별 처리 과정을 보여줍니다.

분석 아카이브

과거 분석 이력 수와 피드백 통계를 확인합니다.

진단 정보

시스템 모델 파일 존재 여부, 학습 상태 등 기술적 진단 결과를 표시합니다.

RF-Dual 낙상 판단 기준과 XG-Posture 역할

RF는 bbox 기반 낙상 확률을 계산하고, XG-Posture는 sit / lie / fall 경계 설명과 오탐 억제를 담당합니다.

RF 낙상 확률 판단

  • detection_rate / center_y / final_height_ratio — 급격한 하강, 마지막 자세 붕괴, 검출 안정성을 같이 봅니다.
  • motion guard — 움직임이 거의 없거나 controlled-lie 패턴이면 점수를 낮춰 오탐을 억제합니다.
  • decision_state — RF 확률만 높다고 끝내지 않고 XG-Posture와 결합해 safe / posture_only / fall_suspected / fall_confirmed로 구분합니다.

XG-Posture를 같이 쓰는 이유

  • fast-sit vs fall 분리 — 앉기와 낙상을 posture layer가 분리해 RF 단독 오탐을 줄입니다.
  • lie vs fall 설명 — 누운 자세 자체는 posture_only로 두고, 급격한 붕괴가 있을 때만 낙상 경보를 유지합니다.
  • 로그 설명 강화 — posture label, decision_state, explain을 붙여 사용자에게 왜 그렇게 봤는지 한 줄로 설명할 수 있습니다.

분석 결과 카드 해석

분석 완료 후 표시되는 판단 근거 카드의 의미를 설명합니다.

위험도 점수

0%~100% 사이의 위험 확률입니다. RF 확률과 자세/상태 arbitration을 함께 보며, 점수가 높을수록 낙상 패턴에 가깝습니다.

Y축 하강 변위

사람의 수직 위치가 얼마나 내려갔는지를 나타냅니다. 값이 클수록 급격한 하강이 발생한 것입니다.

하강 가속도

하강 속도가 얼마나 빠르게 증가했는지를 나타냅니다. 넘어질 때 급격한 가속이 발생합니다.

자세 높이 비율

영상 후반부에서 자세가 얼마나 낮아졌는지를 나타냅니다. 1 미만이면 넘어진 후 일어나지 못한 상태입니다.

종횡비 변동

사람의 체형이 세로에서 가로로 변한 정도입니다. 큰 변동은 넘어짐을 의미합니다.

관리자 설정

이 페이지는 관리자(admin) 권한이 있는 사용자만 접근할 수 있습니다.

관리자 설정 페이지( /admin/analysis )에서는 학습 데이터 관리, 알림 게이트웨이 설정, 보호자 관리, 알림 발송 이력 조회를 수행합니다.

주요 기능

학습 데이터 관리

새로운 낙상/비낙상 영상 데이터를 업로드하여 모델 학습에 활용합니다. 라벨(Y/N)과 메모를 함께 등록할 수 있습니다.

Baseline 재학습

현재 축적된 학습 데이터를 기반으로 모델을 재학습합니다.

알림 게이트웨이 설정

SMS(문자 메시지) 및 푸시 알림의 활성화 여부, API 키, 발신 번호 등을 설정합니다.

보호자 관리

낙상 감지 시 알림을 받을 보호자의 이름, 연락처, 관계를 등록합니다. 여러 명의 보호자를 추가할 수 있습니다.

알림 발송 이력

과거에 전송된 알림의 내역(수신자, 시간, 상태)을 확인합니다.

멤버 관리

멤버 관리 페이지( /members )에서는 시스템 사용자 목록을 확인하고, 새 사용자를 초대하거나 기존 사용자를 제거할 수 있습니다.

멤버 초대

  1. 멤버 초대 버튼을 클릭합니다.
  2. 초대할 이메일 주소를 입력합니다.
  3. 역할(admin / editor / viewer)을 선택합니다.
  4. 초대하기 버튼으로 등록합니다.

역할 설명

admin모든 기능에 접근 가능 (관리자 설정 포함)

editor분석 실행, 피드백, 게시판 작성 가능

viewer조회만 가능

멤버 검색 및 필터

상단의 검색 필드로 이름/이메일 검색, 역할 필터 버튼으로 특정 역할의 멤버만 조회할 수 있습니다.

마이페이지

마이페이지( /mypage )에서는 내 프로필 정보를 수정하고 비밀번호를 변경할 수 있습니다.

프로필 수정

이름과 연락처를 수정할 수 있습니다. 이메일은 계정 식별자이므로 변경할 수 없습니다.

비밀번호 변경

현재 비밀번호 확인 후, 새 비밀번호(8자 이상)로 변경할 수 있습니다.

게시판

게시판( /posts )은 공지사항 및 자유 게시글을 작성·열람할 수 있는 공간입니다. 게시글 목록에서 글을 클릭하면 상세 페이지로 이동합니다.

자주 묻는 질문

Q. 분석 가능한 영상 형식은 무엇인가요?

MP4, MOV, AVI, MKV, WEBM 형식을 지원합니다.

Q. 웹캠 연결이 안 됩니다.

HTTPS 환경이 아니거나 브라우저에서 카메라 권한을 차단한 경우 연결이 불가합니다. Chrome 또는 Edge 브라우저 사용을 권장합니다. 브라우저 주소창의 자물쇠 아이콘에서 카메라 권한을 확인하세요.

Q. 위험 점수는 어떻게 해석하나요?

0%~100% 사이의 확률값이며, 기준값(Threshold) 이상이면 낙상으로 판정됩니다. 높을수록 낙상 가능성이 높습니다.

Q. 분석 결과가 틀린 것 같습니다.

분석 결과 하단의 "결과 검증 피드백" 영역에서 "틀려요"를 선택하고 실제 정답을 알려주세요. 이 데이터가 모델 개선에 활용됩니다.

Q. 관리자 페이지에 접근할 수 없습니다.

관리자(admin) 역할이 부여된 계정만 접근 가능합니다. 관리자에게 역할 변경을 요청하세요.

Q. 실시간 분석 중 '청크 건너뛰기'가 표시됩니다.

이전 청크의 분석이 아직 완료되지 않아 새 청크를 대기열에 넣은 것입니다. 서버 응답이 느리거나 네트워크가 불안정할 때 발생할 수 있으며, 최신 청크 1건만 유지됩니다.

Q. 보호자 알림이 실제로 전송되나요?

프로토타입 단계에서는 시뮬레이션 모드입니다. 실제 SMS/푸시 알림을 발송하려면 관리자가 알림 게이트웨이 설정에서 API 키와 발신 번호를 설정해야 합니다.
