## 2. 왜 표정 모델을 붙였는가

- 목표는 낙상 판정 대체가 아니라 고통·불안·졸림·주의저하 같은 보조 근거를 추가하는 것
- 낙상/비낙상은 RF-Fall v2가 먼저 판단하고, 표정/상태는 evidence로만 반영
- 얼굴이 안 보이면 감점이나 불안 판정을 하지 않고 '표정 미검출'로 처리

## 6. 런타임 적용 파이프라인

- 프레임 샘플링 → 사람/얼굴 후보 ROI → 얼굴 품질 gate → 82 감정 모델 + 173 상태 모델 → support evidence 생성
- face_detected=false 또는 detection frame 부족이면 보조 점수 0, UI에는 '얼굴/표정 미검출'
- low confidence, 낮은 margin, 높은 entropy는 '표정 근거 약함'으로 낮춰 표시

---

## 7. 문제였던 부분과 수정

- 문제: 얼굴이 안 보이는 프레임도 불안으로 표시되어 설명 근거가 왜곡됨
- 수정: 실제 얼굴 검출률과 frame consistency를 먼저 검사하는 quality gate 추가
- 문제: 표정 모델 추가 후 RTT 증가. 수정: 매 청크 전체가 아니라 낮은 cadence와 캐시/비동기 근거 생성 중심으로 조정

---

## 8. 낙상 판단과 결합 방식

- final 판단 = RF-Fall v2 중심 + XG-Posture 설명 + 하체가림 보조 + 표정/상태 evidence
- 표정 support는 positive-only 보조 신호다. 미검출/정상/저신뢰는 낙상 점수를 올리지 않는다.
- LLM은 모델 결과를 해석하는 설명 보조이며, 최종 판정을 뒤집는 주체가 아니다.

---

## 9. 현실적 한계

- CCTV/웹캠 환경에서는 얼굴이 작거나 가려지고, 낙상 순간에는 얼굴이 바닥/팔/머리카락에 가려질 수 있음
- AI-Hub 82는 일반 감정 데이터라 낙상 직후 통증/의식저하와 직접 일치하지 않음
- 따라서 발표에서는 '표정으로 낙상 예측'이 아니라 '위험 상태 보조 근거'로 설명해야 함
