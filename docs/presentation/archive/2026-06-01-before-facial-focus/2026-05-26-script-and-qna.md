## 짧은 발표 대본

### 0. 표지

안녕하세요. 이번 발표는 기존 구조 설명은 생략하고, 발표 이후 개선한 내용만 짧게 말씀드리겠습니다.

핵심 수치는 세 가지입니다. 운영 모델에 반영된 데이터는 약 1.71TB 이상이고, 낙상 RF F1은 0.9453, 행동분류 macro F1은 0.9234입니다. 발표 수치는 다운로드한 후보가 아니라 실제 운영 모델에 반영된 데이터 기준입니다.

### 1. 교수님 개선 요청

요청받은 내용은 프레임 수 개선, 데이터 추가 수집, 모델 고도화, 가림 대응, YOLO 최신화, 낙상 예측 가능성 검토였습니다.

현재 반영 방향은 데이터는 실제 모델에 반영된 것만 발표하고, 프레임은 화면 표시와 AI 추론을 분리하는 것입니다. 가림은 feature와 guard로 보강했고, YOLO는 바로 교체하지 않고 shadow test로 검증했습니다. 낙상 예측은 단기 예측이 아니라 장기 위험도 예측으로 재정의해야 한다고 판단했습니다.

### 2. 데이터 확보 근거

이번 발표에서는 실제 반영된 데이터 출처를 먼저 보여드립니다.

AI-Hub 71641은 낙상/비낙상 RF 모델에 사용했고, AI-Hub 71461은 stand/sit/lie 행동분류 보강에 사용했습니다. AI-Hub 61은 데이터셋 키이고, 그 안의 095 사람 동작 영상 데이터 원천 파일을 walk/run/sit/lie 보강 후보로 확보했습니다.

### 3. 확보량과 사용량

확보한 데이터 중 운영 모델에 실제 반영된 데이터만 기준으로 정리했습니다.

낙상/비낙상은 약 1.5TB 원천에서 RF 학습 935개와 검증 200개를 사용했습니다. 행동분류는 AI-Hub 71461에서 1,045 samples, AI-Hub 61에서 2,872 windows를 반영했습니다. 추가로 095 원천 파일은 189967 걷기 25.98GB, 189972/189973 앉기 36.42GB, 189975 뛰기 26.37GB, 189976 눕기 9.34GB를 확보해 다음 feature 변환 후보로 분리했습니다. 그래서 현재 운영 행동분류 모델은 3,917 rows 기준입니다.

### 4. 현재 운영 기준 수치

현재 낙상 RF 모델은 threshold 0.465 기준으로 F1 0.9453, precision 0.9406, recall 0.95입니다.

행동분류는 stand, walk, run, sit, lie 5-class이고 macro F1은 0.9234입니다. 평균 수치는 개선됐지만 실제 운영에서 가장 중요한 약점은 stand와 lie 혼동입니다.

### 5. Threshold 조정

이 슬라이드는 낙상 threshold를 왜 0.465로 잡았는지 설명하는 부분입니다. 네 가지 후보를 2x2로 비교했습니다.

0.325는 recall이 98%로 가장 높지만 false positive가 10건이라 오경보 부담이 큽니다. 0.430은 기존 운영 후보였고 precision 92.31%, recall 96.00%로 무난하지만 F1은 94.12%였습니다.

0.465는 precision 94.06%, recall 95.00%, F1 94.53%입니다. recall 0.95를 유지하면서 네 후보 중 F1이 가장 높았습니다. 반대로 0.505는 precision은 95.83%로 가장 높지만 recall이 92%까지 내려가 낙상 누락 위험이 커집니다.

그래서 운영값은 0.465로 잡았습니다. 낙상 서비스에서는 recall을 너무 낮출 수 없고, 동시에 작은 흔들림만으로 fall 확률이 과하게 튀면 오경보가 늘어납니다. 0.465는 이 두 리스크를 가장 균형 있게 줄인 지점입니다.

### 6. 이전 발표 대비 개선

이전 발표 대비 낙상 F1은 0.9074에서 0.9453으로 올랐고, precision은 0.8448에서 0.9406으로 개선됐습니다.

행동분류 Group F1은 0.4949에서 0.9234로 개선됐습니다. 다만 이 수치는 grouped 검증 기준이므로, 실제 환경 hard-case 검증은 계속 필요합니다.

### 7. 프레임 정책

현재 장비에서 실시간 AI 추론 안정권은 3-4fps입니다. 업로드 batch는 8fps까지 가능하지만, 실시간 전체 프레임을 60fps로 서버 YOLO/pose에 넣으면 RTT와 큐 적체가 커집니다.

그래서 현재 방향은 화면은 60fps로 부드럽게 보여주고, AI 추론은 3-4fps로 안정적으로 돌리는 것입니다. 더 올리려면 GPU worker, ONNX 또는 TensorRT 최적화, 카메라별 추론 queue가 필요합니다.

### 8. 가림 대응

가림 대응은 안 보이는 하체를 정확히 복원하는 것이 목표가 아닙니다. 현재 조건에서는 보이는 상체와 bbox로 확률적으로 판단하고, 불확실하면 신뢰도를 낮춰서 설명하는 것이 더 안전합니다.

사용하는 기준은 상체 수직성, 어깨-골반 벡터, bbox 높이와 중심, 중심 이동량, lower-body visibility입니다. 한계도 분명합니다. 하체가 장시간 완전히 가려지면 stand, sit, lie, 제자리 흔들림을 구분하기 어렵습니다.

이 부분을 개선하려면 실제 설치 각도에서 촬영한 하체 가림 영상, 침대/의자 전이 영상, 서기-눕기 오분류 clip이 필요합니다. 장비 측면에서는 높은 시야각, 광각, 가능하면 다중 카메라나 깊이 센서가 도움이 됩니다.

### 9. Confusion Matrix

이 슬라이드는 현재 데이터에서 어디가 약한지 보여주는 진단용입니다.

핵심은 stand와 lie입니다. stand가 sit이나 lie로 섞인 경우가 43건이고, lie가 stand나 sit로 섞인 경우가 62건입니다. 반대로 walk와 run은 비교적 안정적입니다. 그래서 다음 보강은 stand/lie, sit/lie, 하체 가림 hard-case가 우선입니다.

### 10. YOLO Shadow Test

YOLOv8n-pose, YOLO11n-pose, YOLO26n-pose를 비교했습니다.

YOLO11은 confidence가 좋아지는 장점이 있었지만 검출률이 소폭 낮았습니다. YOLO26은 지연과 검출률 리스크가 컸습니다. 그래서 현재는 YOLOv8n-pose를 유지하고, YOLO11을 더 넓은 검증셋에서 shadow test하는 방향이 안전합니다.

### 11. 낙상 예측 모델

낙상 예측은 현재 모델과 다른 문제입니다. 정확히 몇 초 뒤 낙상할지 맞히는 시점 예측은 현실적으로 어렵고, 1~2초 뒤 예측은 사람이 개입하기에 너무 짧아서 사실상 조기 감지입니다.

교수님이 원하시는 진짜 예측은 수십초에서 분 단위로 위험이 올라가는 상태를 미리 알려주는 위험도 예측으로 봐야 합니다. 이를 위해서는 낙상 전 장기 보행, 비틀거림, 불안정 자세, 환경 요인, near-miss 라벨이 필요합니다.

### 12. 결론

정리하면, 현재 운영 수치는 정리됐고 모델 개선 방향도 명확해졌습니다.

다음 성능 향상은 모델을 더 크게 만드는 것보다 실제 환경 가림 hard-case를 수집하고 QA 선별해서 재학습하는 것이 핵심입니다. 다음 작업은 stand/lie와 가림 hard-case 데이터 수집, Group split 재학습, YOLO11 shadow test 확대, 낙상 위험도 예측 데이터 설계입니다.

## 예상 질문과 답변

### Q1. AI-Hub 62 데이터는 왜 발표에서 뺐나요?

다운로드와 후보 검증은 했지만 운영 모델 성능을 개선하지 못했기 때문입니다. 발표에서는 실제 운영 모델에 반영된 데이터만 보여주는 편이 더 명확합니다. 62는 추후 QA 선별 후 다시 사용할 수 있지만, 현재 발표 수치에서는 제외했습니다.

### Q2. 후보 데이터 제외는 실패인가요?

아닙니다. 성능이 낮은 후보가 운영 모델을 덮어쓰지 않도록 막은 것입니다. 이 검증 체계가 있어야 모델을 안전하게 개선할 수 있습니다.

### Q3. threshold 0.465를 고른 이유는 무엇인가요?

recall 0.95를 유지하면서 F1이 가장 높았기 때문입니다. 0.325는 더 민감하지만 오경보가 늘고, 0.505는 오경보는 줄지만 낙상 누락이 늘어납니다. 운영에서는 두 리스크의 균형이 중요해서 0.465가 가장 적합합니다.

### Q4. 가려진 하체를 AI가 추정할 수 있나요?

일부 추정은 가능합니다. 다만 정확한 관절 복원은 어렵고, 보이는 상체와 bbox 기반의 확률적 판단이 현실적입니다. 완전 가림이 길어지면 stand/sit/lie 구분은 본질적으로 불확실해집니다.

### Q5. 가림 문제를 해결하려면 어떤 데이터가 더 필요한가요?

실제 설치 각도에서 촬영한 하체 가림 영상이 필요합니다. 특히 침대/의자 주변 전이, 서기-눕기 오분류, 하체가 잘린 상태의 stand/sit/lie, 제자리 상체 흔들림 clip이 중요합니다.

### Q6. 가림 문제를 해결하려면 어떤 장비가 도움이 되나요?

높은 시야각 카메라, 광각 렌즈, 다중 카메라가 도움이 됩니다. 가능하다면 깊이/거리 센서를 쓰면 사람의 높이와 바닥 근접도를 더 안정적으로 볼 수 있습니다.

### Q7. 왜 60fps로 AI 분석을 하지 않나요?

현재 서버에서 전체 60fps를 YOLO/pose에 넣으면 호출량이 너무 커져 RTT와 큐 적체가 생깁니다. 화면은 60fps로 보여주되 AI 추론은 3-4fps로 안정적으로 돌리는 것이 현재 장비 기준으로 맞습니다.

### Q8. stand와 lie가 왜 많이 헷갈리나요?

하체가 가려지고 카메라 각도가 낮으면 bbox 중심 높이와 상체 형태가 비슷하게 보입니다. 특히 침대나 바닥 근처에서는 직립/누움 feature가 흐려져 stand/lie 혼동이 늘어납니다.

### Q9. confusion matrix를 왜 넣었나요?

성능 숫자만 보여주면 어디를 고쳐야 하는지 잘 보이지 않습니다. confusion matrix는 stand/lie와 sit/lie가 약점이라는 것을 한눈에 보여주고, 다음 데이터 수집 우선순위를 설명하는 근거가 됩니다.

### Q10. YOLO11로 바로 바꾸면 안 되나요?

YOLO11은 confidence는 좋아졌지만 검출률이 소폭 낮았습니다. downstream feature가 YOLOv8n-pose 출력에 맞춰져 있어서 바로 바꾸면 모델 입력 분포가 흔들릴 수 있습니다. shadow test 후 전환하는 것이 안전합니다.

### Q11. 낙상 예측 모델은 가능한가요?

정확히 몇 초 뒤 낙상할지 맞히는 시점 예측은 현실적으로 어렵습니다. 다만 수십초~분 단위로 위험이 올라가는 상태를 예측하는 위험도 모델은 가능성이 있습니다. 이를 위해 낙상 전 장기 행동, 비틀거림, near-miss 라벨이 필요합니다.

### Q12. 다음 작업 우선순위는 무엇인가요?

첫 번째는 실제 환경 가림 hard-case 데이터 수집입니다. 두 번째는 QA 선별 후 Group split 재학습입니다. 세 번째는 YOLO11 shadow test 확대와 장기 위험도 예측용 데이터 설계입니다.
