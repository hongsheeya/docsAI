## 4. 추가 원천 반영 원칙

이번 발표에서는 운영 모델에 실제 반영된 데이터만 본문 수치로 사용한다. 추가 원천은 다운로드 여부보다 검증 성능과 실제 환경 적합성이 더 중요하다.

| 항목 | 기준 |
|------|------|
| 운영 반영 | 기존 validation에서 성능이 유지되거나 개선될 때만 반영 |
| 제외 기준 | 분포 차이로 운영 성능이 떨어지면 발표/운영 수치에서 제외 |
| 다음 반영 방식 | 실제 환경과 가까운 clip을 QA 선별한 뒤 Group split으로 재학습 |

해석:

- 데이터 양보다 실제 환경과 feature 분포가 더 중요하다.
- 발표에는 “다운로드한 데이터”보다 “모델에 실제 반영한 데이터”를 우선 표시한다.
- 다음 재학습은 stand/lie와 가림 hard-case를 우선 선별한다.

## 5. Threshold 운영값 조정

| 후보 | threshold | 결과 | 판단 |
|------|-----------|------|------|
| Recall 우선 | 0.325 | Precision 90.74%, Recall 98.00%, F1 94.23% | 민감하지만 FP 10으로 오경보 부담 |
| 기존 운영 후보 | 0.430 | Precision 92.31%, Recall 96.00%, F1 94.12% | 균형형이지만 F1은 추천값보다 낮음 |
| 추천 운영값 | 0.465 | Precision 94.06%, Recall 95.00%, F1 94.53% | recall 0.95를 유지하면서 F1 최고 |
| Precision 우선 | 0.505 | Precision 95.83%, Recall 92.00%, F1 93.88% | 오경보는 줄지만 FN 증가 |

운영값은 `0.465`로 잡는다. 낙상 서비스에서는 recall이 너무 떨어지면 위험하고, threshold를 너무 낮추면 작은 흔들림에도 fall 확률이 튀어 오경보가 늘어난다. 0.465는 두 리스크를 가장 균형 있게 줄인 지점이다.

## 7. 가려진 부분 예측 방향

가림 대응은 “가려진 관절을 정확히 복원”하는 문제가 아니다. 현재 형편에서는 보이는 상체와 bbox로 확률적 판단을 하고, 불확실성을 함께 표시하는 방향이 안전하다.

| 구분 | 내용 |
|------|------|
| 진행 방향 | 상체 verticality, 어깨-골반 벡터, bbox 높이/중심, 중심 이동량, lower-body visibility를 함께 사용 |
| 현재 가능한 것 | 하체가 일부 가려져도 stand/sit/lie 과판정을 줄이고, walk/run은 실제 displacement가 있을 때만 허용 |
| 현재 한계 | 하체가 장시간 완전히 가려지면 stand/sit/lie와 제자리 흔들림 구분이 본질적으로 어렵다 |
| 필요한 데이터 | 실제 설치 각도에서 하체 가림, 침대/의자 전이, 서기-눕기 오분류 clip, 신뢰도 라벨 |
| 필요한 장비/환경 | 높은 시야각 카메라, 광각, 가능하면 다중 카메라 또는 깊이/거리 센서 |

결론: 지금은 모델 feature 보강보다 “실제 환경 가림 hard-case 데이터”가 성능 향상에 가장 직접적이다.

## 8. Confusion Matrix로 본 보강 우선순위

행동분류 confusion matrix는 현재 데이터에서 어디가 약한지 보여주는 진단용 지표다.

| actual / pred | stand | walk | run | sit | lie |
|---------------|------:|-----:|----:|----:|----:|
| stand | 277 | 0 | 0 | 21 | 22 |
| walk | 0 | 179 | 0 | 0 | 1 |
| run | 0 | 5 | 174 | 1 | 0 |
| sit | 0 | 0 | 4 | 219 | 1 |
| lie | 32 | 0 | 0 | 30 | 369 |

해석:

- `stand -> sit/lie` 혼동 43건, `lie -> stand/sit` 혼동 62건이 핵심 문제다.
- walk/run은 비교적 안정적이다.
- 다음 데이터 보강은 stand/lie, sit/lie, 하체 가림 hard-case가 우선이다.
- 이 matrix는 “무엇을 더 학습할지”를 설명하는 근거로 사용한다.

## 10. 낙상 예측 모델의 현실적 방향

정확히 몇 초 뒤 낙상할지 맞히는 시점 예측은 현실적으로 어렵다. 1~2초 뒤 낙상 여부는 사람이 개입하기에는 너무 짧아 조기 감지에 가깝다.

교수님이 원하는 진짜 예측은 다음처럼 재정의해야 한다.

| 구분 | 방향 |
|------|------|
| 목표 | 수십초~분 단위로 낙상 위험이 높아진 상태를 확률적으로 예측 |
| 필요한 데이터 | 낙상 전 장기 보행, 비틀거림, 불안정 자세, 환경 요인, near-miss 라벨 |
| 모델 구조 | 현재 낙상 감지 모델과 별도 장기 temporal risk model |
| 평가 지표 | risk AUC, calibration, false alarm/hour, warning lead time |

현 데이터만으로 진짜 예측 성능을 정직하게 제시하기는 어렵다. 먼저 조기 감지 안정화, 이후 위험도 예측 연구로 가는 것이 맞다.

## 11. 최종 결론

- 데이터는 확보했다.
- 운영 성능은 낙상 F1 0.9453, 행동 macro F1 0.9234다.
- 발표 수치는 운영 모델에 실제 반영된 데이터만 기준으로 정리했다.
- 프레임은 UI 60fps와 AI 3-4fps를 분리해야 한다.
- confusion matrix 기준으로 stand/lie와 가림 hard-case 보강이 핵심이다.
- 진짜 낙상 예측은 단기 낙상 분류가 아니라 장기 위험도 예측 문제다.

다음 작업은 `실제 환경 가림 데이터 수집 → QA 선별 → Group split 재학습 → YOLO11 shadow 확대 검증` 순서가 가장 현실적이다.
