## 슬라이드 1 — 개요

오늘 리뷰의 목표와 발표 흐름을 먼저 정리해드리겠습니다.

**운영 목표는 세 가지입니다.** 낙상 탐지와 행동 분류를 하나의 화면에서 안정적으로 제공하고, 비낙상 구간에서도 stand·walk·run·sit·lie를 구분하며, 단일 모델이 아닌 역할이 다른 두 모델을 중첩한 RF-Dual 구조로 안정성을 확보합니다.

**이번 정리 범위는 다섯 가지입니다.** RF-Dual 파이프라인 구조 재정리, sit↔lie 경계 보정, 데이터 누수 점검, **각 모델의 threshold 조정 이력 및 성능 전후 비교**, 그리고 한계점과 개선 방향입니다.

발표 흐름은 화면에 보이는 순서대로 진행합니다.

## 슬라이드 2 — 문제 정의

왜 단일 모델만으로는 부족한지부터 설명드리겠습니다.

낙상 탐지는 완전히 다른 두 가지 요구를 동시에 충족해야 합니다.

**왼쪽: 낙상 판정.** "이 장면이 실제 위험한 낙상인가?"를 빠르게 결정해야 합니다. Recall을 최우선으로 설계해서 낙상을 놓치는 경우를 최소화해야 합니다.

**오른쪽: 행동 해석.** 비낙상 상황에서 stand·walk·run·sit·lie를 구분하고 화면에 설명 가능한 결과를 제공해야 합니다.

두 목표가 같은 모델 안에서 충돌합니다. Recall을 높이면 자세 경계가 흔들리고, 자세 정밀도를 높이면 낙상 민감도가 저하됩니다. RF-Dual은 두 역할을 분리해서 이 트레이드오프를 구조적으로 회피합니다.

## 슬라이드 3 — RF-Dual 아키텍처

RF-Dual의 구조와 장점을 설명드리겠습니다.

**구조:** RF binary가 낙상 최종 판정을 담당하고, XG-Posture가 자세·행동 해석을 담당합니다. arbitration 계층이 두 결과를 조합해 최종 5-class 출력을 냅니다.

**첫 번째 장점은 FN 최소화입니다.** RF model의 운영 threshold를 낮게 유지해서 낙상을 놓치는 경우를 최소화합니다. 동시에 XG-Posture가 비낙상 행동 정보를 보강해서 RF 오탐을 억제합니다. threshold를 낮춰도 FP가 폭증하지 않는 구조입니다.

**교수님께서 질문하신 핵심 — 낙상(fall)과 누운 자세(lie)를 어떻게 구분하는가:**

첫째, **delta_y_max**입니다. 낙상은 짧은 시간 안에 수직 이동이 크게 발생합니다 (≥15px). 반면 lie 상태는 처음부터 바닥에 있기 때문에 수직 이동이 거의 없습니다.

둘째, **height_std**입니다. 낙상 과정에서는 bbox 높이가 급변합니다 (≥45). lie는 이미 누운 상태라 bbox가 안정적으로 낮고 변동이 없습니다.

셋째, **final_height_ratio**입니다. 낙상 직후에는 bbox가 낮아집니다 (비율 < 1.0). lie는 처음부터 수평 bbox 상태입니다.

넷째, **fhr_rise_suppressor**입니다. 최종 높이가 오히려 올라가는 경우 — 예를 들어 앉기에서 일어서기 — 는 낙상으로 판정하지 않고 취소합니다.

요약하면: fall은 "서 있다가 쓰러지는 전환 사건"이고, lie는 "처음부터 정적 수평 상태"입니다. 시간축 변화 패턴으로 구별합니다.

## 슬라이드 6 — 전체 파이프라인

전체 판단 파이프라인입니다.

영상이 들어오면 YOLO로 bbox와 keypoint를 추출하고, 시계열 feature를 생성합니다. 이 feature가 RF binary와 XG-Posture에 동시에 입력됩니다. 이후 heuristic boost·guard 후처리를 거쳐 5-class로 재정규화하고, arbitration 계층에서 최종 판단을 내립니다.

초록색 강조 박스가 세 군데 있습니다 — RF binary, XG-Posture, arbitration. 이 세 부분이 RF-Dual의 핵심 의사결정 지점입니다.

## 슬라이드 7 — 모델 성능 현황 — 운영 적용 전후

**RF binary 성능을 운영 적용 전후로 비교합니다.**

**베이스라인 (threshold=0.50):** XGBoost 기본값 그대로 적용한 최초 상태. Recall 91%, FP 10건, FN 9건, F1 90.55%입니다.

**현재 운영 (threshold=0.35 + guard):** threshold를 0.35로 낮춰 FP가 우려되는 부분을 guard·suppressor로 흡수한 형태입니다. Recall 91% 유지, FP 10 → 9로 1건 감소, F1 91.0%로 미세하게 개선됐습니다.

업그레이드의 실질적 효과가 크지 않아 보일 수 있는데, **threshold 조정 과정에서 중간 실험으로 Recall을 최대 94%까지 올릴 수 있다는 가능성을 확인했습니다.** threshold=0.35 단독일 때 Recall 94%·FN 6건 달성. 다만 FP가 13건으로 증가해서 guard로 흡수합니다. guard 파라미터를 추가 튜닝하면 Recall 개선 여지가 있습니다.

**XG-Posture CV 교정:**
기존 StratifiedKFold에서 clip-grouped GroupKFold로 바꿨습니다. Val F1이 0.7035에서 0.4949로 내려갔는데, 이는 성능이 저하된 것이 아니라 실제 일반화 수준으로 기준을 교정한 것입니다.

## 슬라이드 8 — 현재 한계 (stand 데이터 불균형)

현재 시스템의 한계를 솔직하게 공유드리겠습니다.

**문제는 stand 클래스의 데이터 불균형입니다.** stand는 87개인 반면, sit은 480개, walk은 468개, run은 214개입니다. stand가 현저히 적어, 학습 과정에서 stand 클래스가 과소대표됩니다.

결과적으로 서 있는 자세를 sit이나 walk으로 오분류할 위험이 상존합니다. 참고로 017 행동분류 데이터셋에는 stand 전용 레이블 클래스가 없어서 017만으로는 stand 데이터를 충분히 확보하기 어려운 상황입니다.

**해결책은 데이터 추가 수집입니다.** stand 전용 영상을 추가로 수집하면 자연스럽게 해결됩니다. 단기적으로는 HITL 피드백으로 stand 교정 데이터를 점진적으로 축적하거나, 데이터 증강으로 부분 보완할 수 있습니다.

이 문제는 모델 구조의 결함이 아니라 데이터 수집의 문제이므로, 추가 stand 데이터가 확보되면 해결됩니다.

## 슬라이드 10 — 향후 계획

향후 계획은 7단계입니다.

단기 우선순위는 1→2→3 순서입니다. clip-grouped 기준 XG-Posture 재학습 → sit/lie hard-case 회귀 테스트 → 외부 holdout 평가. 이 세 단계가 완료되어야 upright_sit_guard와 grouped CV 교정 효과를 수치로 검증할 수 있습니다.

중기는 feature 세분화와 detector noise 정제입니다.

장기 계획에는 시계열 모델 실험과 함께 **AI Agent 자세 설명 기능**을 추가할 예정입니다. 현재 화면에는 숫자와 레이블(stand, sit, lie 등)만 표시되는데, LLM을 연동하면 실시간으로 감지된 자세와 맥락을 자연어로 설명할 수 있습니다. 예를 들만 궁바닥에 누워 2분이 지났는데도 일어나지 않고 있습니다. 낙상 위험 좋합니다 알림이 필요합니다” 같은 형태로 운영자가 바로 이해할 수 있는 설명을 제공하는 것이 목표입니다.

## 슬라이드 11 — 결론

마무리입니다.

**RF-Dual은 두 가지 핵심 장점을 유지합니다.** FN 최소화와 모델별 독립 개선.

threshold 조정 관점에서 보면 — threshold=0.35로 낮추는 실험으로 Recall을 최대 94%까지 끌어올릴 수 있음을 확인했고, guard를 추가해 FP를 베이스라인보다 1건 줄인 상태로 현재 운영 중입니다. guard 파라미터 추가 튜닝으로 Recall을 더 높일 여지가 있습니다.

이번 릴리즈에서 sit↔lie 과보정 완화, 데이터 누수 교정, RF guard 강화를 완료했고, 다음은 grouped 기준 재학습 → hard-case 회귀 테스트 → 외부 holdout 평가 순서로 진행합니다.
