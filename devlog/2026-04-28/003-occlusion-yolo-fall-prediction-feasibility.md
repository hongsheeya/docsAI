# 가림 대응·YOLO 고도화·낙상 예측 모델 선행 검토

- **ID**: 003
- **날짜**: 2026-04-28
- **유형**: 분석 문서

## 작업 요약
가려진 부분 예측, YOLO 모델 고도화, 낙상 예측 모델 개발 가능성을 각각 검토했다. 결론적으로 **가림 대응은 보수적 처리 유지가 우선**, **YOLO는 모델 교체보다 배포/추론 최적화가 우선**, **낙상 예측은 즉시 제품화보다 연구 PoC가 적절**하다.

## 1. 가려진 부분 예측 방법 탐색
### 현재 상태
- 이미 `occluded` 태그와 hard-case 관리 체계가 있다.
- 2026-04-07 이력에서 주요 keypoint 가시성이 낮을 때는 움직임을 보수적으로 clamp해, 보간된 keypoint가 허위 움직임을 만들지 않도록 했다.
- 즉, 현재 시스템은 "안 보이면 보수적으로 본다"는 철학에 가깝다.

### 적용 가능성 판단
| 방식 | 적용 여부 | 판단 |
|------|-----------|------|
| 단순 interpolation 확대 | 비권장 | 허위 움직임/자세 생성 위험 |
| visibility-aware clamp | 유지 권장 | 현재 운영 철학과 일치 |
| occlusion-aware 별도 feature 추가 | 가능 | 중기 개선안 |
| 가림 전용 보조 분류기 | 연구 가능 | 추가 데이터 필요 |

### 설명
- 가려진 부위를 "예측해서 복원"하는 방식은 시각적으로는 자연스러워도, 분류기 입력에는 노이즈를 넣을 가능성이 높다.
- 특히 sit/walk 오판 사례처럼, 보간된 keypoint가 없는 움직임을 만들어낼 위험이 이미 확인됐다.
- 따라서 현재는 **복원보다 불확실성 관리**가 더 안전하다.

### 권장안
1. keypoint visibility/confidence를 feature로 직접 반영
2. occlusion score가 높을 때 decision confidence를 낮춤
3. `occluded-fall`, `offscreen-chair` 같은 hard-case를 별도 validation 세트로 운영
4. 가림 복원은 추후 연구용 branch에서만 실험

## 2. YOLO 모델 고도화
### 현재 상태
- person detector fine-tuning 결과는 이미 높다: mAP50 0.989 / Precision 0.990 / Recall 0.983
- 또 RF-Dual은 YOLO single-pass 통합으로 중복 추론을 줄였다.
- 즉, 현재 병목과 오류의 상당수는 "YOLO 정확도 부족" 자체보다 파이프라인/데이터 분포/배포 경로에 있다.

### 적용 가능성 판단
| 개선안 | 적용 여부 | 우선순위 |
|--------|-----------|----------|
| imgsz / stride / profile 튜닝 | 가능 | 높음 |
| ONNX / TensorRT / OpenVINO | 가능 | 높음 |
| detect/pose 경로 분리 최적화 | 가능 | 중상 |
| 최신 YOLO 계열 재학습 | 가능 | 중간 |
| 대형 모델 교체 | 가능하나 비권장 | 낮음 |

### 설명
- 현 단계에서 가장 ROI가 큰 것은 **모델 교체보다 추론 엔진/배포 최적화**다.
- detector 자체 성능은 이미 높아, 더 큰 모델로 바꿔도 정확도 대비 속도 손해가 클 수 있다.
- 반대로 ONNX/TensorRT, lower imgsz, GPU 분기, edge profile 분리 등은 속도 개선 효과가 직접적이다.

### 예상 효과
1. **경량화/엔진 최적화**
   - 처리 시간 감소 가능성 높음
   - fps와 지연시간 모두 개선 가능
2. **최신 모델 교체**
   - 특정 장면에서 탐지 안정성 개선 가능
   - 그러나 재학습/검증 비용 큼
3. **pose/detect 분리**
   - 낙상 탐지는 detect 우선, 자세 분석은 필요 시만 pose 호출하는 구조 가능
   - 가장 실용적인 중기 구조 개선안

## 3. 낙상 예측 모델 개발(가능성 검토)
### 정의부터 다름
낙상 탐지는 "이미 발생한 낙상"을 맞히는 문제지만,
낙상 예측은 "1~3초 뒤 낙상 가능성" 같은 사전 위험 징후를 맞히는 문제다.

### 필요한 추가 조건
1. **pre-fall 라벨 정의**
   - 예: 낙상 직전 0.5초 / 1초 / 3초를 positive로 볼지 결정 필요
2. **prediction horizon 설계**
   - 1초 예측과 5초 예측은 완전히 다른 문제
3. **transition 라벨 품질**
   - 비정상 보행, 휘청거림, 중심 붕괴, 벽 의존 등 전조행동 확보 필요
4. **False alarm 허용 정책**
   - 예측 모델은 본질적으로 FP가 높아질 가능성이 큼

### 적용 가능성 판단
| 항목 | 판단 |
|------|------|
| 단기 운영 기능 | 낮음 |
| 연구 PoC | 중간 |
| 장기 연구 과제 | 높음 |

### 예상 리스크
- 현재 데이터셋은 "낙상 직전 전조행동" 라벨이 부족하다.
- 낙상 예측은 낙상 탐지보다 annotation 비용이 높다.
- 운영 알람으로 바로 쓰면 false positive가 급증할 수 있다.

### 권장안
1. 즉시 제품 기능으로 넣지 않음
2. 연구실 수집 데이터에서 pre-fall 시퀀스를 별도 태깅
3. `transition`, `uncertain`, `occluded` 태그를 활용해 PoC 데이터셋 구성
4. 먼저 risk score/early warning 보조지표 형태로 실험
